## Encore 0.41.1

**A file on a broken disk of a pooled library no longer reads as "storage problem" forever.** With mergerfs (or a
similar pool), one disk can go read-only – an ext4 journal abort remounts it `emergency_ro` – while the pool and
every other disk stay writable. Encore used to call every write to a file on that disk a storage problem, wait for
the storage, find it fine, and fail again on the next try.

### What changed
- **The error is pinned on the file.** When a write fails with "Read-only file system" (or the disk refuses the
  name) Encore probes the file's own folder at once. When that folder can be written, the message says so and names
  the folder it tested and, in a mergerfs pool, the disk the file is really on:
  *import failed: write /music/Coldplay/Singles/Coldplay - ♾.opus: Read-only file system (os error 30) –
  /music/Coldplay/Singles can be written, this file can't (the file is on /mnt/media2/music/…): it is on a
  read-only disk of the pool, or the disk refuses its name – not the source, and not the whole storage.*
  Such an error no longer pauses imports or makes a request wait for the storage.
- **Tagging works around the read-only disk.** Tag from release (and an import's tagging) writes such a file anew:
  a copy next to it lands on a writable disk, is tagged and takes the old name, so the pool shows the new copy. The
  old copy stays on the read-only disk and the activity log says so. When the pool won't let the new copy take the
  name, it keeps one of its own ("Song (2).opus") and the library follows it.
- **Imports too.** An import that replaces a file on the read-only disk, or moves one off it, puts the new file
  next to it under a free name instead of failing; the old file stays where it is.
- Retry and Tag again always run the step again; nothing was cached. The error was simply true every time.

### Emoji and symbols in file names
- New setting, Settings → Library → **Emoji and symbols in file names**: *Keep them* (the default, as before),
  *Write them as words* (♾️ → "Infinity", ❤️ → "Red Heart", 🌎 → "Earth Americas") or *Plain ASCII names only*.
  Every emoji-only title still gets a name of its own, the same on every import. Only file and folder names
  change; tags and the library keep the real titles. For disks that refuse emoji (exFAT, FAT, some NAS shares).
- Whatever the setting, a new file whose name the disk refuses is written once more with the name in words.

### If you see this message
Look at the disk it names: `dmesg | grep -i ext4` shows a journal abort, `findmnt` shows `emergency_ro` on it.
Stop Encore, unmount the pool and that disk, `fsck` it, mount both again and start Encore.
