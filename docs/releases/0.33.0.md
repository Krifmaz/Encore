## Encore 0.33.0

A file manager for admins: look through the music folders on the server, upload, move, rename and tidy files, and bring a folder into the library, moved in or kept where it is, without opening a shell on the server.

### New
- **Files** (admins only): Settings → System → Files on the website and in the desktop app; on the phone, Settings → Server → Files or *Files* in Home's ⋯ menu. Members never see it, and every request behind it checks that the caller is an admin.
  - **The folders it can reach:** the library (`library_path`), the staging folder, Soulseek's download folder, the torrent and Usenet download and watch folders that are there on the disk, and Trash (`/config/trash`). Each shows its free space; a folder Encore can't write to says *Read-only*. Nothing outside these folders can be reached: `../`, absolute paths and look-alike characters are refused with "That path is outside the folders Encore may use", and a link that points outside is listed but never followed.
  - **Browse:** a tree of the folders, breadcrumbs, a path box, sorting by name, size or date (folders first), 500 entries at a time. Songs the library knows show their artist, title and length. Picking works like a desktop file manager (click, Ctrl/⌘-click, Shift-click, Ctrl+A), and so do the keys: Enter opens, Backspace goes up, Delete moves to trash after asking, F2 renames. Every row has one ⋯ menu, which a right-click also opens.
  - **Upload** files or a whole folder (its subfolders kept). On the website you can also drag them onto the page; the desktop app takes files dropped on its window (Windows, macOS and X11; on Wayland use *Upload*). When a name is taken: *Keep both* ("Song (2).flac", the default), *Replace* (the old file goes to Trash) or *Skip*. A progress panel shows the file being sent and has *Stop*; a cut-off upload leaves nothing behind.
  - **New folder, Rename, Move** (a folder picker over the folders that can be written). Songs moved or renamed inside the library keep their place in the library: likes, playlist entries and plays follow them.
  - **Move to trash, Restore, Delete forever, Empty trash.** Trash is the only place files are deleted for good. Restore puts a file back where it was and brings its songs back with their likes and playlist entries. Items stay in Trash until you delete them.
  - **Edit tags** of any audio file (title, artist, album, album artist, track, disc, year, genre); an emptied field removes the tag. For songs the library has, *Edit song details…* opens the usual Fix song dialog.
  - **Import…** on a folder: every album in it, matched like the match review (*Other matches* searches MusicBrainz, Deezer, Apple Music, Discogs or by audio), then tagged and moved into the library. Nothing in the library is replaced (a taken name gets " (2)"), songs that were in the library already keep their likes, plays and shares, and nothing is deleted for good: what is left in an emptied folder (covers, .nfo, .cue, logs) and the library's lower-quality copies and loose singles it replaces go to Trash. With **Keep the files where they are** on, the songs join the library where and as they are: nothing is moved, renamed or retagged, and the folder is added to *Extra library folders* (not for Staging, which Encore clears, nor for a folder that holds the library).
  - Every change is a line in the activity log (who, what, from where to where).
- **Extra library folders** (Settings → Server → Library → *Library & tagging*, one folder per line; env `ENCORE_LIBRARY_EXTRA_ROOTS`). Encore scans them with the library folder (at start, on schedule and with the Library page's *Scan*), and never moves, renames or retags their files on its own: *Organize files*, renaming after *Edit details* and a release picked in the match review leave the files where they are, and the automatic re-tag of albums made from Deezer or Apple data, *Auto-tag untagged* and *Find missing artwork* skip them. Your own edits still write tags, and *Find missing artwork* keeps a cover it finds for them in Encore's own cover store instead. An import's duplicate check never deletes a song there: both copies stay. A folder that isn't there at scan time, or is empty while the library has songs in it (a disk not mounted leaves an empty folder), is skipped and its songs stay in the library; the scan's line names it, and the activity log says it once.

### Before you update
- **No database change:** the schema stays at 27, as in 0.31.
- **Docker:** the file manager sees the server's folders as the container sees them. A folder you want to import and keep where it is has to be mounted into the container first; *Extra library folders* takes paths inside the container.
- **Trash lives in `/config/trash`.** When `/config` is on another disk than your music, *Move to trash* copies the files there (after checking there is room) and removes the originals, so trashing a large album takes a while and needs space on the config disk.

### What to test
- **Upload a folder** of two FLACs into Staging, then *Import…* it into the library with *Keep the files where they are* off; check the album in the library.
- **Move after a like:** like one of its songs, move the album to another folder of the library, and play the liked song from Liked Songs.
- **Rename, Move to trash and Restore** a file and a folder; then *Delete forever* and *Empty trash*.
- **Keep in place:** *Import…* a folder outside the library with *Keep the files where they are* on; check the songs are in the library, the files have not moved or changed, and the folder is listed under *Extra library folders*. Add a song to that folder by hand and press *Scan* on the Library page.
- **Refusals:** type `../` or `/etc` in the path box; sign in as a member and check Files is not there.
- **The phone and the desktop app:** the same steps from Settings → Files, an upload through the system picker on the phone, and a file dropped on the desktop app's window.
- **Uploads that stop:** close the tab or press *Stop* during a large upload, and check no hidden `.encore-upload` file is left in the folder (a torrent client's own `.part` files next to it are never touched).
