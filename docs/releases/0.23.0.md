## Encore 0.23.0

- **Soulseek is now run by Encore with slskd as its engine – inside the Encore container.** Encore's own Soulseek client is gone, and so is the choice between it and an external slskd container. Encore downloads [slskd](https://github.com/slskd/slskd) from its GitHub releases, writes its settings from Encore's (login, listen port, downloads folder, shared library, upload slots), runs it headless on 127.0.0.1 with an API key only Encore knows, and restarts it when it stops (after 5 s, then waiting longer each time, up to 5 minutes) or when the settings change. Search, browse, the Soulseek page, picks and the request pipeline work as before; the Soulseek page's *Transfers* now lists uploads too.
  - **First start after the upgrade**: Soulseek shows *not installed* and nothing is downloaded by itself. Open *Settings → Download tools* and press **Install** on *slskd – Soulseek engine* (or switch on its automatic updates).
  - Your Soulseek login, port, share, upload slots, downloads folder and ranking settings carry over unchanged. The *Client*, *slskd URL*, *slskd API key* and *Listen port from a file* settings are gone (old saved values are ignored); an slskd container from an older setup can be removed.
  - *Settings → Apps & sources → Soulseek* shows the engine's state – not installed, starting, running (with its version), crashed (with the reason) or waiting for the VPN. *Test connection* and Diagnostics show the engine's state, whether it is signed in to the Soulseek server, and the VPN line. Its output is kept in `/config/slskd/encore-run.log` (rotated at 5 MB).
- **Soulseek through the built-in VPN, leak-free**: with the VPN on, slskd connects only through a local SOCKS5 proxy into the WireGuard tunnel – the Soulseek server, peer messages, transfers and the distributed network all use it (checked in Soulseek.NET: every connection kind takes the same proxy options), and the server's address is looked up through the VPN's DNS. slskd listens on 127.0.0.1 only; the VPN's forwarded port becomes the listen port and is relayed in from the tunnel. With *Keep Soulseek off while the VPN is down* (on by default) slskd is stopped until the tunnel is up.
- **Cadenza as an updatable server tool**: server-side Cadenza processing can run the `cadenza` program from Cadenza's GitHub releases instead of the engine built into Encore. *Settings → Download tools* lists *Cadenza (server processing)* with **Update** and *Use the built-in engine*; the download is checked against the release's SHA256SUMS and must describe itself before it is used. If it fails to start, the render falls back to the built-in engine. The render label and *Server processing* show which engine is used (*Cadenza 2.2.0 (updated)* or *Cadenza (built in)*), and renders are redone after an engine update.
- **Engine settings drawn by the engine**: *Server processing* has an *Engine settings* block built from the settings the active Cadenza engine describes (filter, dither, headroom, soft clip, GPU processing and device when the engine has them). Each listener's own filter and dither choices still apply per stream.
- **Download tools check everything**: the daily *Update download tools* task checks yt-dlp, streamrip, Cadenza and slskd on every run and lists each one in its result (e.g. "slskd 0.26.1 available", "Cadenza up to date"). It installs updates only for tools whose automatic switch is on: yt-dlp and streamrip on by default, Cadenza and slskd off by default (manual updates).
- **Settings cleanup**: the built-in-client wording is gone from Settings, the VPN help and Diagnostics; Soulseek is simply Soulseek, run by Encore, and the word slskd only appears where you install or update it.
- **Cadenza 2.2.0**: the built-in engine and the downloadable `cadenza` program are both Cadenza 2.2.0 – a CUDA GPU upsampler (falls back to the CPU on its own if the GPU fails mid-song) and three new error-correcting DSD modulators (*asdm5ec*, *asdm7ec*, *asdm7ec8*, up to about 128 dB in the audio band at DSD64).
