## Encore 0.30.0

### The phone app inside
The phone app's code was reorganised without changing what it does; most of this is invisible, these parts are not:

- **One sound engine.** The sound effects (EQ, crossfeed, balance, mono) always run in Cadenza, the same engine as the server, also for the fading-out song of a crossfade or overlap (before, that tail used a second copy of the effects written in Kotlin; it is still not upsampled on the phone). A build of the app without the Cadenza library plays without effects instead of falling back to that copy; the APKs on the Releases page always have it.
- **Less copying per buffer.** The sound now reaches Cadenza through memory both sides share, instead of a new copy of every buffer in each direction (most buffers when the phone upsamples to 176.4 or 192 kHz).
- **Phones with 16 KB memory pages** (some Android 15 and newer devices): the Cadenza library is built for them, and every release APK is checked for it.
- **One artist page.** An artist opened from the Library tab (or without network, or one MusicBrainz doesn't know) now opens the same artist page as everywhere else, with what the library has: the picture, the counts, *Play*, *Shuffle*, *Share link* and the albums as "In your library". The year bar along the edge of that page is gone.
- Fixed in passing: an artist page no longer shows a link button that opens nothing when MusicBrainz sends an empty link.

### The phone app updates itself
Settings → This device → **Updates**, as on the desktop app: the version, *Look for a new version when Encore starts* (on by default; at most once a day), *Check for updates*, and when there is one, *Install 0.30.x* with *What changed* and *View on GitHub*. A new version is also announced once with a short note when the app opens.

- The app reads the newest release on GitHub itself (the server is not involved, so it works for every account, not only admins) and downloads `Encore-android-<version>.apk`.
- Before anything is installed, the download is checked: its SHA-256 against the release's `SHA256SUMS` and GitHub's own checksum of the file when the release has them, and always the APK against the app on the phone (the same app, a newer version, signed with the same key). A file that fails any of these is deleted and never installed.
- The first time, Android asks you to allow Encore to install apps (*Allow from this source*); the update goes on when you come back. Android then asks you to confirm the update, except on Android 12 and newer where it may let Encore update itself without asking. Encore closes while it installs; open it again afterwards. Android Auto uses the updated app as well.
- Debug builds can't update themselves; they show where the releases are.

### Songs on the phone without the server
*Download for offline* is in the ⋯ of a song, an album, a playlist and the player (as on the website). The songs are saved as music files in **Music/Encore/<Artist>/<Album>/** – `01 - Title.flac`, the file as it is on the server, tags included – so other music players see them too, and they stay when the app is removed.

- A file this phone can't play as it is (DSD, APE, WavPack, ALAC …) is saved as lossless FLAC the server makes, marked *FLAC (converted)*. *Download again in original quality* is there for those copies.
- A downloaded song plays from the phone, with or without a connection, and uses no data; the Signal path says *Downloaded copy on this device* with its quality. Turn off *Play downloaded songs from this device* (Settings → This device → Downloads, as on the website) to stream them while the server can be reached, for example with the server's Cadenza processing; without the server the copy always plays.
- **Offline mode**: when the server can't be reached and songs are saved here, the app says *Offline – the server can't be reached. Downloaded songs play.* with *Retry*; the Library tab shows what is downloaded and the other tabs wait. Plays and likes made meanwhile are kept and sent when the server answers again (*Back online – 3 plays sent*), so Last.fm and ListenBrainz get them too. A play or like that fails during a short gap waits the same way and goes with the next one the server takes, also when only Android Auto is in use.
- **Library → Downloaded** lists them by album (Play, Shuffle, search, Remove download); **Android Auto** gets a *Downloaded* tab that works without the server; covers and lyrics are saved with the songs.
- **Settings → This device → Downloads**: the room they take, each album with its size and a remove button, *Remove all*, and *Play downloaded songs from this device*.
- On Android 8 and 9 the first download asks for access to the phone's storage. A notification shows the progress (two songs at a time).

### Bug reports from the phone
**Bug reports** is in the menu behind your picture on Home and in Settings → This device, with the number of reports that have something new for you, as in the website's side bar. It is the website's page: the status tabs, the Bug / Not a bug / How do I… chips, the search, *New report*, and each report with its replies.

- *New report*: the kind, a title, what happened and up to six pictures from the phone's photo picker. The page you came from, the app's version and the phone (model, Android version, screen size) go along. A photo the server would refuse as it is (a HEIC photo, one over 8 MB or larger than 8192 pixels a side) is sent as a smaller JPEG instead.
- In a report: the pictures open full size, text files open as text; reply with text and pictures.
- Admins also get *Everyone* / *Mine*, the status select, *Delete*, and *Export* (the list as it is filtered, or *Export this report*): the zip opens Android's share sheet, so it goes to a mail, a chat or Files.

### Every Settings page on the phone
Settings on the phone is now the website's Settings, page for page and in the same order, one page at a time: **You** – Account, Appearance, Language, Playback, Connections, This device; for admins also **People** – Users & permissions, Invites; **Server** – General, Library, Downloads, Integrations, Server processing, Email & notifications, Auto-download, Contribute, Blocked, Scheduled tasks; **System** – Diagnostics. When the server's check found a newer Encore, admins see "Encore … is available – Diagnostics" at the top.

- **Appearance**: the presets, the theme (Encore, Dark, OLED black, Light, Match device), the accent colour (ten swatches or any colour as hex) and the background. They are kept in your account as on the website, so the look follows you to every device.
- **Language**: how titles in another script show and into which language, saved to your account, with the Translator's state. Fixing one title (⋯ → Edit translation) stays on the website.
- **Connections**: Jellyfin, Plex, Navidrome, ListenBrainz, Last.fm, YouTube Music, Spotify, Tidal and Deezer, with the same switches, Import playlists, Sync now and Disconnect. Spotify, Tidal and Last.fm open their sign-in in a browser tab and the phone waits up to 2 minutes for it (Plex: 4 minutes, as on the website). Sign in to Encore in the phone's browser first: the server needs that to take the account back. Last.fm counts as connected once it can scrobble.
- **This device**: the server this phone is signed in to, the device name and Your devices, Downloads, Updates, Bug reports, and the crash reports waiting to be sent.
- **Users & permissions** and **Invites**: each user as a card with the role, weekly limit, auto-approve, permissions, password reset, disable and delete; what new members start with; the sign-up mode, New invite and Copy link.
- **The Server pages** are drawn from the server's own list of settings (the one the website uses since 0.29), so a setting a newer server adds shows up without an app update: each field with its help, Show advanced, Test with its result line, Save per card (only what changed is sent), and "🔒 Set by … in your compose/env" on what the environment sets. Downloads also has the download tools with their updates, the Soulseek status with the VPN block and Start now, the Tidal sign-in for streamrip and the YouTube sign-in card; Server processing has Cadenza with its cache and engine settings. Scheduled tasks lists every job with its last run and Run now.
- **Saved secrets** (passwords, keys, tokens) keep what is saved unless you type a new one. The server's owner can show and copy them on the Server pages, as on the website (not the WireGuard config); each view is written to the server log. While a secret is shown, the screen is kept out of screenshots and the recent-apps preview, and the secret hides again when you leave the page. On Android 13 and newer a copied secret is kept out of the keyboard's clipboard preview.
- **Diagnostics**: every check with the raw answers, the Server block, where settings come from and Copy report; the server's update card (Check now, Restart server, Update now); the database backups (Back up now, Upload a backup…, Restore…, and Download, which saves the file in the phone's Downloads folder with a notification for the progress; Android 8 and 9 ask for storage access first); and the app's crash reports.

### For developers
- `clients/android/README.md` describes the app as it is now; the original plan moved to `docs/archive/android-native/PLAN.md`.
- The playback service is split into `Scrobbler`, `AdaptiveQuality`, `ServerCadenza`, `Autoplay`, `Resume`, `CurrentStream` and `playback/output/` (`OutputRouter`, the effects processor, USB output); the service keeps the Media3 wiring.
- One lenient JSON layer (`core/Json.kt`) replaces the readers each file had; the Discover, For you, Requests, picker, playlist, account and leaderboard answers are `@Serializable` models; the session's stream information is one JSON extra (`encore.stream_info`).
- The JNI crate (`clients/android/cadenza/rust`): `nativeProcess(handle, io: ByteBuffer, frames, out: ByteBuffer?): Int` over direct buffers, `nativeFetch` for an output larger than the buffer, and `build.rs` linking Android builds with `-z max-page-size=16384`. CI (`apps.yml`, android-native) fails when a `.so` in the APK has a LOAD segment aligned below 16 KB or `zipalign -c -P 16` fails.
- Unit tests: `app/src/test` (JUnit 4.13.2, a test-only dependency; the plain rules of offline songs, updates, bug reports and Settings) runs in CI as `:app:testDebugUnitTest` after the APK is built.
- Offline songs live in `features/offline/`: `OfflineStore` (MediaStore Audio on Android 10+ with `IS_PENDING`, plain files with `WRITE_EXTERNAL_STORAGE` on 8–9; the index, covers and lyrics), `OfflineWorker` (downloads with `X-Encore-Decoders` and `/info`'s `offline_ok`), `OfflineMode` (reachability, the outbox with the 0.28 list form of `POST /api/library/plays`), `OfflineIndex` / `OfflineOutbox` (plain rules, unit tests in `app/src/test`), `OfflineUi`. `StreamResolver` plays a saved copy through its `local` variant; `BrowseTree` has the Downloaded node (also the root for an `isOffline` browser). Android 10+ allows only audio in `Music/`, so there the index (`.encore-index.json`), covers and lyrics are in the app's own storage; on 8–9 the index is `Music/Encore/.encore-index.json`. The manifest gains `WRITE_EXTERNAL_STORAGE` with `maxSdkVersion="28"`.
- Bug reports live in `features/bugs/`: `BugRules` (pure Kotlin: kinds, statuses, the queries, the lines, which pictures go as they are; unit tests in `app/src/test`), `BugReportsApi` (the `/api/bug-reports` calls; the multipart upload streams each picture from the picker's URI), `BugAttachments` (`PickMultipleVisualMedia`, the JPEG made with `ImageDecoder` on 9+ or `BitmapFactory` and the EXIF turn on 8), `BugReportsScreen`, `BugReportScreen`, `NewBugReportSheet`. Routes `Screen.BugReports(from)` and `Screen.BugReport(id)`. The export is shared through `androidx.core.content.FileProvider` (authority `<applicationId>.files`, `res/xml/file_paths.xml`: `cacheDir/shared/` only).
- Unit tests: `app/src/test` (JUnit 4.13.2, a test-only dependency; the plain rules of offline songs, updates and bug reports, 46 tests) runs in CI as `:app:testDebugUnitTest` after the APK is built.
- Settings live in `features/settings/`: `SchemaForm` / `SchemaModels` / `SchemaRules` draw the Server pages from `GET /api/admin/settings/schema` (the field types, `when` rules, environment locks, advanced fields, Test and Save with only the changed keys); one file per hand-written page (`AppearanceScreen`, `ConnectionsScreen`, `ThisDeviceScreen`, `UsersScreen`, `InvitesScreen`, `AutoDownloadScreen`, `ContributeScreen`, `BlockedScreen`, `TasksScreen`, `DiagnosticsScreen`) and the cards (`ServerExtras`, `YouTubeCard`, `TidalSignIn`); the calls are in `data/api/SettingsApi.kt` with the website's paths and bodies. `BackupDownload` fetches a backup with the app's client (the session goes only to the signed-in server, redirects included) into Downloads through MediaStore on Android 10+. `SchemaRules` and `SettingsRules` are plain Kotlin with unit tests.

### What to test
- **Playback after the reorganisation**, each on the phone: play, pause, next, previous, seek (also in a Data saver stream and with server processing on); the notification and lock screen; Bluetooth buttons; Auto quality on a slow connection (the "Connection is slow" and "Connection recovered" notes); server processing (the badge "→ Cadenza", "(pre-rendered)" on the second song, the fall-back note when the server's Cadenza is off); a song the phone can't decode (it plays as FLAC from the server).
- **Plays and now playing** reach the server, Last.fm and ListenBrainz as before (half the song or 4 minutes; a song faded out by a transition counts once).
- **Resume**: close the app while playing and open it (the queue comes back paused), and the crash recovery (force-stop while playing: it plays on when the service restarts within 2 minutes).
- **Keep going with a shuffle of the whole library** at the end of a queue.
- **Sound effects and song transitions**: an EQ preset, crossfeed, balance and mono audibly apply; Crossfade, Overlap and Smart overlap between two songs, with effects on, sound as before and the fading song keeps its effects.
- **Cadenza on this phone**: upsampling on (Signal path shows the filter and the rate), a filter change mid-song restarts it at the same spot; with a USB DAC (Android 14+) bit-perfect on and off.
- **Android Auto and the car**: browse, voice play, the Like / Shuffle / Repeat / Lyrics buttons, the lyrics card, Encore Lyrics.
- **Remote**: this phone seen and controlled from the web (play, pause, seek, volume, play a queue here), and the phone controlling another device.
- **Artist pages**: from the Library tab's artist grid (the counts, *Play*, *Shuffle*, *Share link*, the albums), and from a song's artist name (unchanged).
- **Updates on the phone** (needs a release newer than the installed APK, signed with the release key): Settings → This device → Check for updates shows "Encore … is ready to install." with What changed; Install downloads with progress, asks once for *Allow from this source*, then Android's confirm screen; after it Encore opens on the new version (Settings → About). Cancel the confirm screen and press Install again (no second download). Turn *Look for a new version when Encore starts* off and on; the note "Encore … is available – Settings → This device" comes once per version. A debug build shows "This build can't update itself".
- **Offline songs** (Android 10+ and, if you have one, Android 8 or 9): *Download for offline* on a song, an album and a playlist (the notification counts them; Android 8–9 ask for storage access once); the files appear in Music/Encore/<Artist>/<Album>/ with their tags and play in another music player. A DSD or APE song comes as *FLAC (converted)*. Library → Downloaded, the Signal path (*Downloaded copy on this device*), *Remove download*, Settings → This device → Downloads (sizes, per album, *Remove all*). Airplane mode, then open the app: the offline banner, the Library tab with the saved songs, the other tabs greyed; play, skip, seek, like a song, listen past half of one; turn the network back on: *Back online – 1 play sent*, the like is on the website. Android Auto offline: the *Downloaded* tab plays. Delete a saved file in a file manager: it leaves the list at the next start. Turn *Play downloaded songs from this device* off: the next downloaded song streams (the Signal path shows the stream); on Auto quality a downloaded song after a lowered one says nothing about the connection.
- **Bug reports on the phone**, as a member and as an admin: Home → your picture → Bug reports, and Settings → This device → Bug reports. New report with a title, a description and pictures: a screenshot, a camera photo (also a HEIC one and one over 8 MB: it arrives as a JPEG, upright) and more than six at once (only six are kept, with a note); without a title or a description the sheet says what is missing. The report opens after Send; on the website it shows the page (Home or Settings), the app version and the phone. Reply with and without pictures; tap a picture (full size) and a .txt or .log file someone attached on the website (its text). As admin: Everyone / Mine, the status select (the reporter sees the new status), Delete, Export and Export this report (the share sheet offers the zip; open it: reports.md, reports.json, files/). The number on Settings → This device → Bug reports goes up when the admin answers and down once the report is opened.
- **Settings on the phone**, as a member, an admin and the owner: every page opens and matches the website. Change the accent colour on the phone and see it on the website. Save a Server card (only the changed setting moves; the website shows it), Test on a card, Show advanced, a setting locked by the environment (greyed, with the 🔒 line). As owner: Show and Copy a saved password (a screenshot shows black while it is shown; it is hidden again after leaving the page). Connections: Spotify, Tidal or Last.fm from a phone browser signed in to Encore, and Plex. Diagnostics: Back up now, then Download (a notification, the file in Downloads; Android 8–9 ask for storage access). Downloads: Soulseek Start now, the Tidal sign-in, the YouTube card.
