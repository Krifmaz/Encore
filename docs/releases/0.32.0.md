## Encore 0.32.0

Plugins: Encore's download sources, download clients, tools and connections become plugins you install, update, switch off and remove one by one under Settings → Plugins, without a new Encore image. Plugins written by other people install from a zip or a URL and run in a sandbox. An upgraded server keeps everything it used, with no new setup.

0.32 was not released on its own: it ships in **0.33.0** together with 0.31 and 0.33. The combined notes, with what to do before you update from 0.30, are in [0.33.0.md](0.33.0.md). An upgrade from 0.30.0 runs everything under *Before you update* below on its first start.

### New
- **Settings → Plugins** (admins; website, desktop app and phone, under Server right after Downloads). The catalog: **yt-dlp** (YouTube Music and links, with the YouTube sign-in on its card), **streamrip** (Qobuz, Tidal, Deezer), **Soulseek (slskd)** (with the VPN for Soulseek), **Torrents & Usenet (Prowlarr)** with one plugin per client (qBittorrent, Transmission, Deluge, rTorrent / ruTorrent, SABnzbd, NZBGet and the two watch folders), **Cadenza (server processing)**, the **Translator**, and the **Jellyfin**, **Plex** and **Navidrome** connections.
  - Each card has the plugin's status, *Install*, *Update* (or *Update to 2026.10.14*), *Test*, *Logs* (the last 200 lines, *Copy*), *Disable* / *Enable*, *Remove* and an *Update automatically* switch, and the plugin's settings: the source cards that were on Downloads (streamrip, Soulseek, Torrents & Usenet, yt-dlp, YouTube sign-in) moved there with their extras (Tidal sign-in, the streamrip config reset, the VPN block, the Soulseek status). Cadenza keeps its settings on Server processing and the media servers on Integrations; their cards link there.
  - Downloads keeps *Download pipeline* and *Release types*. The *Download tools* card is gone: its tools are plugins now. Old links (`#/settings?s=streamrip`, `slskd`, `torznab`, `ytdlp`, `youtube`, `tools`) open the Plugins page at the right card.
  - Programs live in `/config/plugins/<id>/`: yt-dlp and streamrip in venvs of their own, slskd, Cadenza and llama.cpp from their releases. Downloads from releases are checked against their sha256 before anything is unpacked (slskd and llama.cpp against the sha256 GitHub lists, with a line in the log when it lists none), and a new version is used only after it starts and reports its version; a failed update keeps the version that worked.
  - The scheduled task **Update plugins** (was *Update download tools*, same schedule) checks every installed plugin, installs the new versions of those with *Update automatically* on, and installs a program that is missing.
  - The download picker's tabs say when a source's plugin is not installed or switched off ("Install the yt-dlp plugin under Settings → Plugins"), with a link. The tabs, their order and `source_order` are unchanged.
- **Plugins you add**: *Upload plugin* (a zip up to 200 MB) or *Install from URL* (an https address of a zip or a `plugin.toml`, or `owner/repo@ref` and `owner/repo/folder@ref` from a public GitHub repository). They are marked *Third-party*, run in the sandbox below, and a source plugin gets its own tab in the picker, after the built-in ones; its id can go into `source_order` too. The format is protocol 1 of the plugin SDK (`plugins/sdk/encore_plugin.py`); [docs/plugins/](../plugins/README.md) explains how to write one and has an example, `docs/plugins/example-tone/`, a source that "downloads" sine tones as FLAC. `plugins/tools/plugin-check.py` runs a plugin folder the way Encore does.
- **The plugin sandbox**: the Plugins page shows the level this host allows. *Full isolation*: a plugin you add runs under bubblewrap and sees only its own folders, the download it writes and, when it asks, your music read-only and the network. *Limits only, see the compose option*: limits on memory, processor time and processes, low priority and a cleared environment, but it can read what Encore can. Settings and passwords reach a plugin only on its input, never in its command line or environment.

### Before you update
- **The database moves to schema 28 on the first start** (the new `plugins` table), after Encore saves a copy in the `backups` folder of `/config` (Settings → Diagnostics → Backups). To go back to 0.31, put that copy back before starting the older image; the folders the plugins took over are where they were, so the older image runs on them.
- **What an upgrade takes over.** On the first start, every plugin that was in use is taken over where it is (nothing moves) and switched on with its settings and its old auto-update switch:
  - yt-dlp: always (every image before plugins had it, and pasted links went through it whatever *YouTube Music* said); with *YouTube Music* off it stays off, and links and the last-resort step keep working;
  - streamrip: a copy in `/config/tools/venv`, or streamrip on with a Deezer ARL, a Qobuz token or a Tidal sign-in (`/config/streamrip/config.toml` is used where it is);
  - Soulseek: the slskd in `/config/tools/slskd` (its database in `/config/slskd` stays), or Soulseek on with a login;
  - Cadenza: `/config/tools/cadenza`, or server processing on;
  - the Translator: only when its program and model are both in `/config/tools/translator` (a model is gigabytes, so the switch alone downloads nothing). From 0.33 on, translated and romanized titles also come without it (official names, the romanization built into the server and DeepL; see the 0.33 notes), and the Translator is only the last of those sources;
  - Torrents & Usenet with the client Encore used (any `torrent_client` that names no other client is qBittorrent, `rutorrent` is rTorrent, any `nzb_client` that names no other is SABnzbd), when Prowlarr is set up; Jellyfin, Plex and Navidrome when their address is set.
  The activity log names what was taken over. A fresh install starts with every plugin available and none installed.
- **The image no longer contains yt-dlp and streamrip.** If yours ran on the image's own copies (nothing in `/config/tools/venv`), the plugins install them in the background on the first start: yt-dlp's newest release and streamrip v2.4.10 (the version and its update switch checked as the image did), into `/config/plugins/`. That needs the network once; the cards say *Installing…* meanwhile, and a failed install (no network yet, a proxy, PyPI or GitHub down) is tried again by itself after 1, 2, 5, 10 and 30 minutes, then every hour, at every start and by *Update plugins*, with a line in the activity log for each failed try. Requests that need streamrip or yt-dlp meanwhile wait for it ("Waiting for the streamrip plugin to finish installing", at most an hour) instead of going to another source. An `ENCORE_YTDLP` you set is your copy: nothing is installed beside it. Encore's reading of streamrip's update switch from its own code works with the plugin's copy too.
- **Dockerfile:** no `pip install` of yt-dlp and streamrip, no `/opt/tools` and no `INSTALL_STREAMRIP` / `STREAMRIP_REF` build arguments; `bubblewrap` added; a pinned uv (`UV_VERSION=0.12.21`, in `/opt/uv`) and Python 3.14 in `/opt/python` stay for the Python plugins, with a link for every 3.14.N name so a `/config/tools/venv` made by an older image keeps running; nodejs and ffmpeg stay. `docker exec encore yt-dlp` and `docker exec encore streamrip` no longer work: the programs are under `/config/plugins/<id>/<version>/venv/bin/` (or `/config/tools/venv/bin/` when taken over).
- **The sandbox line on a Docker host** says *Limits only, see the compose option*: Docker's default seccomp profile does not let bubblewrap make namespaces (and on Ubuntu and Debian hosts its AppArmor profile forbids the mounts). Nothing needs to change for the catalog's plugins. For full isolation of plugins you add, the README's [compose option](../../README.md#the-plugin-sandbox-and-the-compose-option): `security_opt: [seccomp=unconfined, apparmor=unconfined]`. [docs/plugins/SANDBOX.md](../plugins/SANDBOX.md) explains what each level hides and each reason the line can give.
- **The streamrip command template** (*Command template (advanced)* on the streamrip card) is no longer run through a shell: it is split into words and each word filled in, so `;`, `|`, `$(…)` and `VAR=value` in it are plain words now. The default template is unchanged. A program you chose yourself still wins over the plugin's copy: the streamrip program setting (`streamrip_bin`) for streamrip, `ENCORE_YTDLP` for yt-dlp.
- `YTDLP_AUTO_UPDATE=false` now keeps *Update plugins* from updating yt-dlp by itself.
- `/api/system/tools`, `/api/system/tools/{id}/…` still answer in their old shape for this release, from the plugins; scripts should move to `/api/plugins`. The 0.30 apps' *Download tools* card keeps working against them: its *Update automatically* switches and the plugin cards' switch are the same setting, and *Use the bundled version* is no longer offered for yt-dlp and streamrip (there is no bundled copy; asking anyway is refused instead of removing the plugin).
- A plugin you add updates by itself (its *Update automatically*) only while a new version asks for no more than the one you installed: one that wants the network, more hosts or folders, higher limits or another update address waits for *Update* on its card, which says why.
- The programs Encore starts itself (yt-dlp, streamrip, slskd, Cadenza, the Translator) no longer get Encore's own settings in their environment (`ENCORE_*` and every variable a setting reads).

### What to test
- **Upgrade your install** and check downloads keep working with no new setup: Settings → Plugins lists yt-dlp, streamrip and Soulseek as installed and on, their cards have your settings (ARL, Qobuz login, Soulseek login, VPN), the activity log says what was taken over; request one song from each source (a Deezer or Qobuz album, a Soulseek FLAC, a YouTube Music song, a pasted link) and check Soulseek stays signed in.
- **A fresh install** (a new config folder): every plugin under *Available*, none installed, the picker's tabs say to install; *Install* yt-dlp with one click and request a song.
- **Each card**: *Update*, *Disable* (the picker tab then says it is switched off), *Enable*, *Logs*, *Test*, *Remove* (it moves back to *Available*; your settings stay for the next install).
- **The sandbox line on your Docker host**; if it says *Limits only*, try the compose option, recreate the container and check it says *Full isolation*.
- **Upload the example plugin**: make the zip with `cd docs/plugins && python3 -m zipfile -c example-tone.zip example-tone/`, *Upload plugin*, confirm the third-party question; *Test* passes; *Pick download* on a song you can spare, the *Example tone* tab, search "tone": seven tones, FLAC 16-bit. Pick *Concert A*: Encore writes a tone as long as that song and imports it in its place (the audio checks may turn it away, since it does not sound like the song; the request's history then says so, which passes this test too). Delete the tone afterwards. Then *Disable* (the tab says it is off) and *Remove* (gone, its folder deleted).
- **Install from a URL**: `Krifmaz/Encore/docs/plugins/example-tone@main` (works while the repository is public: the archive is fetched without a token), and the https address of a plugin zip you host.
- **Your Internet Archive plugin** through *Upload plugin*: it installs, says *Ready*, and its card has Preferred format, Collections and Items to inspect; then a search and a download from archive.org (not reachable where this was built). [docs/plugins/owner-internet-archive-notes.md](../plugins/owner-internet-archive-notes.md) lists what a read of it found.
- **Cadenza**: *Update* on its card, then a stream with server processing on.
- **The phone and the desktop app**: the same Plugins page (list, *Install*, *Test*, *Logs*, settings), an upload through the phone's file picker.
- **The picker and requests otherwise unchanged**: the same tabs in the same order, *Pick download* and automatic requests through the same sources.
